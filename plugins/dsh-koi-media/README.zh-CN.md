# dsh-koi-media

中文 | [English](./README.md)

处理入站图片转述、持久图片库存，以及视频消息首帧提取。

## 它做什么

- 监听真人入站消息中的 `Image: /path`，在提示词组装前执行视觉调用。
- 在 order `94` 的独立注入段中写入明确标注、只描述不判断的转述。
- 用 `mediaRoot` 校验图片路径，检查类型和大小，并按类别记录识图失败。
- 按内容 hash 保存收下图片的描述、发送者、时间和持久副本。
- 按描述或发送者找回图片，并返回可直接发送的路径。
- 用 `ffmpeg` 提取视频首帧，返回临时路径供直接读取。

## 设计思路

- **自动转述解决“看到路径不等于看见图”。** 原图进入上下文时只是一行文本路径；如果等 agent 自己决定调用 `read_image`，它可能完全没看图。入站后先跑一次视觉，能在生成前提供客观材料。
- **转述边界必须明确。** 视觉提示只要求人物、颜色、动作和图上的文字，不猜意图、不下结论，并限制在 120 字左右。注入时说明这是“机器转述，不是你的眼睛”，要求 agent 说“图上写着/图里有”，不能说“我看见”。
- **图中文字是数据，不是指令。** 图片里可能出现提示注入。注入段明确标为不可信数据，用开始/结束标记包住，并要求模型不执行图中任何命令。
- **`mediaRoot` 是信任边界。** 自动识图和 `keep_image` 都会解析最近存在祖先的真实路径。即使字面路径在根目录内，只要符号链接逃到外面，或经过软链与 `..` 穿越，也会被拒绝。
- **先查大小再读文件。** 默认 8 MiB 上限避免超大图被读入或上传；超限直接返回明确错误，不消耗视觉调用。
- **库存必须复制，因为源目录是临时的。** `keep_image` 把通过校验的图按内容 hash 复制到持久目录；复制失败时只记描述，并明确说原图没存下来。
- **持久附件有不可忽视的代价。** 识图会向 DSH 附件库写入副本，该库没有删除接口且按内容去重。注入文字会说明这件事，避免把“已转述”误当成“已收图”。
- **当前代码不压缩图片。** 冗余的压缩钩子已经删除。超限时直接拒绝，比在识图前静默改图更简单，也更可预期。

## 配置

| 键 | 默认值 | 作用 |
| --- | --- | --- |
| `dir` | 解析后的 KOI 数据目录 | `stickers.json` 与库存媒体目录的基准。 |
| `maxBytes` | `8388608` | 识图前允许读取的最大图片字节数。 |
| `mediaRoot` | `~/.dsh-qqbot/media` | 只有真实路径仍在此根内的文件可识图或收起。 |
| `vision.provider` | 空 | 显式覆盖视觉 provider。 |
| `vision.model` | 空 | 显式覆盖视觉 model。 |
| `vision.maxImages` | `3` | 单条入站消息最多转述多少张图。 |
| `vision.maxTokens` | `2048` | 单次视觉请求的输出预算。 |
| `vision.timeoutMs` | `30000` | 单次视觉请求的超时毫秒数。 |
| `vision.statsPath` | `<dir>/media-silent.json` | 分类识图失败计数器文件。 |
| `silentPath` | `<dir>/media-silent.json` | `vision.statsPath` 的旧别名。 |

`MODEL_PROVIDER` 与 `MODEL_NAME` 是模型路由兜底输入；`FFMPEG_PATH` 可覆盖视频工具使用的可执行文件。

## 接口

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `koi-media` | 插件 id | 包导出的挂载名。 |
| `tools` | 注入服务 | 图片库存和视频工具注册所必需。 |
| `agent/inbox/spliced` | 事件订阅 | 在提示词组装前启动识图任务。 |
| `agent/inbox/claimed` | 事件订阅 | 把识图任务挂到真正 claim 这条消息的回合。 |
| `session/event` 的 turn end | 事件订阅 | 清理本轮状态并让排队过久的任务过期。 |
| `system-prompt/assemble` | 事件订阅 | 等待本轮任务并注入转述。 |
| `koi:vision-feed`，order `94` | 注入段 | 带抗提示注入边界的机器转述。 |
| `keep_image` | 工具 | 把通过的媒体文件复制进持久库存。 |
| `recall_image` | 工具 | 按描述或发送者查找库存。 |
| `qqbot_describe_video` | 工具 | 提取并返回本地视频首帧。 |

## 验证

在仓库根目录运行：

```bash
node plugins/dsh-koi-media/test-stickers.mjs
```

测试逐条打印 `✅` 或 `❌`，结束时输出 `N 通过 / 0 失败`；全部通过时退出码为 `0`。

## 说明 / 限制

- 自动转述同时需要 LLM stream 服务和带 `saveImage` 的 attachment 服务。
- 每次调用都会重新解析路由，顺序为插件覆盖、面板固定配置、活会话、环境变量。
- `mediaRoot` 必须存在且能通过 `realpath` 解析；根目录本身不算可读取的图片路径。
- 每张图一次视觉调用。120 字是提示词要求，不是硬输出截断。
- 库存返回的是持久副本，但收图时源路径必须仍在 `mediaRoot` 内。
- 视频抽帧依赖可用的 `ffmpeg` 进程，并把临时 JPEG 写到系统临时目录。
- 随包 patch 中有 `maxSide`，但当前媒体代码不读取、不应用它，也不做图片缩放。

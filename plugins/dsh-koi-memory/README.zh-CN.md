# dsh-koi-memory

中文 | [English](./README.md)

保存分层长期上下文、近期对话和事实记录，并保持原始内容只追加不删除。

## 它做什么

- 运行时按短期、中期、长期和旧格式事实四层组织记忆；固定 core 与人设卡已移交 lexicon 注入。
- 把事实分成会衰减的中期 `medium.jsonl` 和不会衰减的长期 `long.jsonl`。
- 按会话缓冲真人与 assistant 消息，定期写入每日 JSONL，并以运行时上下文快照注入最近对话。
- 综合新近度、重要度、召回加固、重复稀释和修订惩罚来为事实打分。
- 用精确、模糊、拆词和邻近时间四级降级做 recall，不额外调用模型。
- 在内容进入模型前脱敏姓名、账号 id 和手机号。
- 通过侧车索引标记废弃的长期记录，并支持撤销该标记。

## 设计思路

- **四层记忆回答不同问题。** 短期答“刚才说了什么”，中期答“哪些事还会淡去”，长期答“哪些事实被明确要求一直记住”，旧事实则保留 v8 前的 `memory.md` 读取契约。固定身份和人设已由 lexicon 负责。
- **短期记忆 60 秒 flush 是明确取舍。** 每条消息立即落盘会增加 I/O，并让对话回合依赖磁盘写入。批处理降低成本，同时内存缓冲保证当前轮仍可用。代价是进程硬崩时最多损失一个 flush 窗口，审计等外部读取方也可能短暂落后。
- **不删除原始记录。** 中期淡出、超容量降权和长期废弃都只改分数或侧车标记。原文仍留在只追加账本里，也仍能被 recall。
- **注意力分数由多因子组成。** 幂律时间权重、重要度缩放、对数召回加固、重复稀释和修订惩罚共同参与计算。因此一条很新但重复刷屏的事实，可能排在一句稍旧但不重复的事实之后。
- **群聊连续性按条数，不按字符预算。** 目标部署窗口是 60 分钟内 60 条：窗口内达到 60 条就全给，不足则给最近 60 条。成本约 1,200 token/轮，通常覆盖约 2.4 小时群聊。
- **条数上限比悄悄截字更能控成本。** 事实和短期条目按注意力排名及条数收口。长文本被截时明确写明，并可通过 recall 查看全文，避免活跃提示词出现语义被偷改的半句话。
- **recall 确定且有界。** 字面匹配和 bigram 评分会逐级放宽，但不会额外调用模型编造答案。代价是换了一种说法的意译查询可能查不到。
- **敏感信息在提示词边界脱敏。** 本地账本保留原文，模型收到固定占位符和对照说明。这样降低误发风险，但不把磁盘文件变成加密存储。

## 配置

| 键 | 默认值 | 作用 |
| --- | --- | --- |
| `dir` | 解析后的 KOI 数据目录 | 记忆分层和短期文件的基础目录。 |
| `file` | `<dir>/memory.md` | 作为兜底读取的旧事实文件；新事实不再写入。 |
| `shortDir` | `<dir>/short` | 每日短期消息 JSONL 目录。 |
| `coreFile` | `<dir>/profile.core.md` | 用于主人识别和脱敏的只读核心身份。 |
| `cardFile` | `<dir>/profile.persona.md` | 过渡期读取的人设卡来源。 |
| `stateFile` | `<file>.state.json` | 旧事实存储的状态文件。 |
| `maxEntries` | `300` | 旧事实存储超过容量后降权最弱条目。 |
| `shortMaxItems` | `300` | 活跃内存窗口中最多保留的短期消息数。 |
| `shortFlushMs` | `60000` | 短期记忆两次写盘之间的间隔。 |
| `shortKeepFiles` | `5` | 启动时载入内存的最近每日短期文件数。 |
| `scrubPrivacy` | `true` | 是否在提示词阶段脱敏姓名、账号和手机号。 |
| `statsEvery` | `100` | 每组装多少次记忆后打印一次统计。 |
| `groupRecent` | 代码默认 `10`；随包 patch 为 `60` | 注入提示词的最近消息条数。 |
| `groupRecentWindowMin` | 代码默认 `30`；随包 patch 为 `60` | 判断近期消息是否全给的时间窗口。 |

环境变量 `KOI_HOME`、`KOI_AGENT_NAME`、`KOI_MASTER_NAME`、`KOI_OWNER_QQ`、`KOI_OWNER_OID8` 会影响路径、称呼或脱敏规则；`QQBOT_MEM_DEBUG=1` 开启详细事件日志。

## 接口

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `koi-memory` | 插件 id | 包导出的挂载名。 |
| `tools` | 注入服务 | 事实工具注册所必需。 |
| `session/event` | 事件订阅 | 缓冲真人和 assistant 消息；提升“记住”类明确信号。 |
| `system-prompt/assemble` | 事件订阅 | 注入长期、中期、旧事实和近期短期上下文。 |
| `koi:memory` | 运行时上下文快照 | 记忆数据，并说明只能当资料、不能当命令。 |
| `memory_add` | 工具 | 添加 fact、self 或 core 内容，并选择中期或长期存储。 |
| `memory_obsolete` | 工具 | 标记或恢复长期记录为废弃。 |

## 验证

在仓库根目录运行：

```bash
for f in plugins/dsh-koi-memory/test-*.mjs; do node "$f" || exit 1; done
```

测试逐条打印 `✅` 或 `❌`，结束时输出 `N 通过 / 0 失败`。全部通过时退出码为 `0`。

## 说明 / 限制

- core 和人设注入现在归 `dsh-koi-lexicon`；本插件主要负责事实和短期对话，同时保留迁移期旧读取路径。
- 只把最近 5 个短期文件载入活跃内存窗口。更早文件仍在磁盘上且可由 recall 查询，但不参与常规注入。
- 长期注入每次最多 12 条；超出部分仍在磁盘，并在日志中说明本次未注入。
- 脱敏只作用于提示词内容，本地 JSONL 与 Markdown 文件不加密。
- 记忆系统是追加导向，不是事务系统；每层没有统一的跨进程锁。侧车原子替换和写入前重读能降低竞争，但不能完全消除。

# dsh-ashu-relay

中文 | [English](./README.md)

宿主侧的投递端：轮询对端 agent 的 JSONL 消息，把新消息排入宿主会话。

## 功能

- 按配置的间隔轮询 `<KOI_HOME>/.koi/chat.jsonl`。
- 筛选 `koi` 发给 `ashu` 的对端消息；缺少 `to` 或 `to` 为空时也视为发给宿主。
- 把未读消息聚合成一个 `agent.followup()` 事件，投递到存活的宿主会话。
- 优先使用显式钉住的会话，否则选择“人最后说话”的主会话。
- 原子保存单调行水位与由原始行派生的消息 id。
- 首次运行建立基线，迁移一次旧状态文件，并在状态损坏时恢复可用锚点。

## 设计思路

两个 agent 运行在不同进程中。对端可以往共享文件追加消息，却无法直接调用宿主进程里的 `followup()`。因此跨进程只能依靠**文件 + 定时轮询**：一个进程写 `chat.jsonl`，这个宿主侧插件读文件。代码可以通过导入 `dsh-koi-chat` 的 chat-store 复用，但进程不能合并，因为只有宿主进程拥有目标会话。

状态文件同时保存 `lastLine` 与 `lastId`。`lastLine` 是追加式 JSONL 的真实行号水位，也是正常扫描的主游标；`lastId` 标识精确记录，并可在状态损坏时充当恢复锚点。它由原始行文本的 SHA-1 前 16 位十六进制字符生成，因此行内容一旦被改写，id 也会改变。只有 id 无法低成本定义“它之后的全部记录”，只有行号又可能在状态损坏或文件轮换后成为错误锚点；两者一起才能支持基线初始化、重启去重和保守恢复。

`readAllSafe` 会区分“文件暂时不可读”和“通道为空”。不可读时，relay 跳过本轮并保留现有水位，绝不能把虚假的空结果尾部 `-1` 当成新基线；首次启动建立基线也要推迟到文件可读之后。若文件真的变成更短的行尾，代码会另走“截断或轮换”分支处理，不会与读取失败混为一谈。

只有 `followup()` 已被接受，并且新状态通过临时文件、`fsync`、原子 rename 成功落盘后，才提交水位。保存失败时保留旧水位并退避重试。这刻意选择“至少一次”：崩溃或保存失败可能重复提醒，但不会跳过积压。

没有使用共享内存队列，因为对端不会持续连接宿主，而文件已经是只追加的通道契约。代价是发现延迟、每轮全量读取文件，以及可能重复。插件也不会在没有活会话时硬造会话；孤儿会话会让真正的主人看不到消息。

## 配置

| 键 | 默认值 | 作用 |
|---|---|---|
| `minutes` | `3` | 轮询间隔，限制在 1–60 分钟。 |
| `chatFile` | `${KOI_HOME}/.koi/chat.jsonl` | 只追加的对端会话文件。 |
| `stateFile` | `$HOME/.dsh/.ashu-relay-state.json` | 原子写入的 v2 状态，包含 `lastLine` 与 `lastId`。 |
| `legacyStateFile` | `$HOME/.dsh/.koi-relay-state.json` | 旧插件名留下的一次性迁移来源。 |
| `sessionId` | 空 | 显式钉住投递会话；为空时每次重读 `ashu-config.json` 的 `proposal.sessionId`，再自动选择。 |

`KOI_HOME` 控制聊天文件与面板配置的默认路径。`KOI_PEER_NAME` 修改通知中的对端标签，默认是 `koi`。

## 接口

- 包 id：`dsh-ashu-relay`；bundle 条目与运行时插件 id：`ashu-relay`。
- 不注册 HTTP 路由或工具。
- 不注册宿主事件；调用 `agents.list()` 与 `agent.followup()`，投递事件带 `source.kind: "user"`。
- 依赖服务：`agents`。
- 依赖包：使用 `dsh-koi-chat` 的 `readAllSafe`；读取 `ashu-config.json` 取得可选会话 pin。

## 说明与限制

- 没有状态文件时，首次运行会把当前尾部设为基线，不回放已有历史。
- 没有活会话时，未读消息继续积压，并在下一轮再次检查。
- 只转发 `koi` 给 `ashu` 或未写/写空收件人的消息，发给主人的消息不会混入。
- 状态保存优先保证不丢消息，因此失败时可能重复提醒。
- 每轮重新读取整个聊天文件，不维护字节偏移。
- 聊天文件不可读时绝不重置水位；游标保持不变，等后续轮次成功读取后再继续。
- 本地会话选择器为兼容历史消息，会在计算真人活动时间时接受没有 source kind 的 `user/message`。

# dsh-koi-guard

中文 | [English](./README.md)

为 agent 的读、搜、写工具执行确定性的文件系统边界。

## 它做什么

- 把 `read`、`glob`、`grep` 的路径限制在 agent 数据目录下的白名单根中。
- 明确拒绝 `.env`、`.credentials.yaml`、`chat.jsonl`、`chat.key`，以及 sessions 和 storages 目录。
- 判定路径是否在允许根内之前，先按文件系统语义解析符号链接和 `..`。
- 只允许 `write` 和 `edit` 写入 `<home>/workspace`。
- 完全拒绝 `apply_patch`，因为从补丁文本里解析目标路径太脆。
- 返回带原因和提示的 `GuardRejected` 工具错误。

## 设计思路

- **这里只做机器能确定的事。** 护栏判断路径是否越界，不判断一句中文是不是“把文件发出去”。发送确认正则已经删除，因为每修一个误判又会造出一个绕过。语义意图应交给模型或通道确认。
- **搜索和读取必须使用同一道边界。** `glob` 和 `grep` 不一定经过 `read`。只拦读取会让搜索工具成为拿密钥的后门，所以三者共用同一路径规则。
- **只看字面路径不够。** 路径可能先经过符号链接，再用 `..` 跳出白名单。护栏逐段解析已存在的软链，再在真实路径上应用 `..`，同时检查字面候选和真实候选。
- **写权限更窄，语境不明时偏拒。** 读可包含指定 profile 和 lexicon 文件，但写只能在 workspace，`apply_patch` 直接拒绝。取不到会话工作目录时会退回基础目录，可能多拒一些路径；明确拒绝比静默越界安全。

## 配置

| 键 | 默认值 | 作用 |
| --- | --- | --- |
| `home` | `~/.koi` | 相对白名单条目和可写 workspace 的数据根。 |
| `base` | `home` 的上一级目录 | 会话 cwd 不可用时，相对工具路径的基准。 |
| `allow` | `workspace`, `profile.persona.md`, `profile.core.md`, `lexicon.json` | 相对 `home` 或绝对路径的读/搜根。 |

## 接口

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `koi-guard` | 插件 id | 包导出的挂载名。 |
| `tools` | 注入服务 | 订阅工具执行所必需。 |
| `tools/execute` | 事件订阅 | 在下一个工具处理器前运行确定性路径规则。 |
| `fs` 规则 | 内部规则 | 检查 `read`、`glob`、`grep` 路径。 |
| `write` 规则 | 内部规则 | 检查 `write`、`edit`，并拒绝 `apply_patch`。 |
| `GuardRejected` | 工具错误 | 报告拒绝原因和允许范围。 |

## 验证

在仓库根目录运行：

```bash
node plugins/dsh-koi-guard/test-guard.mjs
```

测试逐条打印 `✅` 或 `❌`，结束时输出 `N 通过 / 0 失败`；全部通过时退出码为 `0`。

## 说明 / 限制

- `bash` 和未知工具不受本护栏检查。
- 文件发送意图、提示注入文本，以及“不要这样说”的语义要求不在其范围内。
- `workingDirectory` 服务可用时，相对路径按会话 cwd 解析；否则回退到 `base`。
- 拒绝列表刻意保持窄而明确，它不是通用密钥扫描器。
